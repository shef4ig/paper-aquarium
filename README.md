# Бумажный мир (Paper World)

Самостоятельная копия проекта «Бумажный аквариум» под отдельный поддомен
(`world.fantasy-games.ru`). Вместо аквариумов — комнаты, вместо рыб — бумажные
куклы-персонажи, плюс декор.

Базовый аквариум не затрагивается: у мира свой `server.js`, свои ассеты и свой
каталог данных `data/rooms/`. Общего рантайма нет — это «вариант A» (независимая
копия), поэтому уронить аквариум отсюда невозможно.

Без внешних рантайм-зависимостей: голый Node + three.js из `vendor/`.

## Запуск

```
cd world
node server.js         # http://localhost:8100/
```

## Как это устроено

- **Комнаты фиксированы контентом.** Реестр — `assets/world/rooms.json`
  (`id`, названия, фон, `scrypt`-хеш токена разблокировки). Один вид журнала =
  один QR = одна комната.
- **Открытие по QR.** Ссылка вида `/r/<id>?k=<token>`. Токен — секрет из журнала;
  на сервере хранится только хеш. «Открыта» — свойство устройства
  (`localStorage['world.rooms']`), сервер о разблокировке не помнит.
- **Набор комнаты** — `assets/world/room-set.json`: базовые фигурки (`bases`) с
  точками крепления (`anchors`), наряды (`garments`) с привязкой к базе и
  anchor, декор (`decor`). Все спрайты — в `assets/world/sprites/**`.
- **Персонаж двумя путями:** из каталога (`catalog.js`) или по фото
  (`doll-capture.js`). Фото — **ключ** к сборке, а не источник пикселей: с него
  берутся только идентификаторы, сцена собирается из эталонов.
- **Сцена** (`room-scene.js`) — 2.5D на three.js: фон-плоскость + спрайты.
  Кукла собирается композитом эталонов в offscreen-canvas.
- **Расстановка** сохраняется в `data/rooms/<id>/state.json`; сервер принимает
  только валидные идентификаторы из набора комнаты (в мир попадают только
  эталоны).

## Демо-ключи разблокировки

Для встроенных комнат (замени токены на свои через `tools/gen-unlock.js`):

| Комната | QR-ссылка |
|---------|-----------|
| bedroom | `/r/bedroom?k=bedroom-key` |
| kitchen | `/r/kitchen?k=kitchen-key` |

## Подготовка эталонов (офлайн)

Реальные ассеты нарезаются из страниц журнала автоматически (без ручной разметки).
Фон-локации и объекты (фигурки, одежда, декор) уже вырезаны из `world_assets/`.

Пайплайн:

```
# 1. Фон комнаты из локации (ресайз до 1600px)
powershell -File tools/resize.ps1 -In <лока.png> -Out assets/world/backgrounds/<room>.png -Max 1600

# 2. Нарезка объектов со страницы (фон определяется по периметру автоматически)
powershell -File tools/slice-page.ps1 -In <страница.png> -OutDir tools/_slice<NN> -Prefix p<NN>

# 3. Сборка room-set.json + rooms.json из нарезок
#    Классифицирует по аспекту: высокие (<0.8) — базовые фигурки, широкие — наряды/декор.
node tools/build-from-slices.js
```

- `slice-page.ps1` — авто-нарезчик: находит объекты на цветном/белом фоне
  (заливка от краёв, фон = медиана периметра), режет каждый в PNG с прозрачностью.
  На System.Drawing (.NET), без внешних зависимостей.
- `build-from-slices.js` — классификация и сборка манифеста; конфиг комнат
  (какая страница → какая комната, токены) — в шапке файла.
- `gen-unlock.js` — salt+hash для токена вручную.
- `prep-world.js` + `prep-plan.json` — альтернативный путь с явным планом
  (когда нужна точная ручная раскладка/anchors).

Исходные страницы журнала — в `world_assets/` (в git не идут).

## Проверка

```
node tools/test-doll-capture.js    # юнит распознавания на синтетике
```

Сценарный чек-лист (ручной): открыть по QR → каталог (персонаж + наряд, декор)
→ фото-сборка → выйти и вернуться (расстановка восстанавливается) → закрытая
комната на главной показывает подсказку про QR.

## Деплой

`Dockerfile` + `docker-compose.prod.yml` — отдельный контейнер за Traefik,
свой том `data/`. Никакой связи с контейнером аквариума.
